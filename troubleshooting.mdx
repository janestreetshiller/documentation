<h2 id="troubleshooting">Record the symptom first</h2>

<p>Start with the step that stopped you. Keep the message you saw, leaving out passwords and private information. To begin again, use <a href="/quickstart#quickstart-mac">the Mac quickstart</a>.</p><dl className="docs-steps"><dt>The download has not appeared</dt><dd>In <a href="https://ouros.md/dashboard#/app">Download and install</a>, choose <strong>Download Ouros for Mac</strong>. While it says “Checking your download access…”, wait for the result. If it asks you to sign in, finish signing in and return to Download and install. If it reports an error or timeout, use the message to decide whether to retry now or later. “Your download is starting” means to check your browser’s downloads; installation still happens on your Mac.</dd><dt>macOS asks whether to open Ouros</dt><dd>For the normal downloaded-app confirmation, choose <strong>Open</strong> for the copy you downloaded from your Ouros account. If macOS instead says the app is damaged, cannot be verified, or will damage your computer, stop and keep the exact warning. Use <a href="https://support.apple.com/en-us/102445">Apple’s explanation of Mac app alerts</a>.</dd><dt>Sign-in finished in the browser, but Ouros is still waiting</dt><dd>Keep Ouros running and return to the browser page opened by that sign-in request. Follow <a href="#recover-signin">the browser-to-app checks</a> below, then check the account status in Ouros.</dd></dl><p>For website or Gateway availability, open <a href="https://ouros.md/status">Service status</a>. If you are checking from Terminal, this read-only request fetches the same page:</p><div className="codeblock"><pre><code>curl --include --fail-with-body https://ouros.md/status</code></pre></div><p>A successful fetch returns <code>200</code> and <code>text/html</code>. Read it as a page. That response does not diagnose your account, Mac or provider connection.</p><dl className="docs-steps"><dt>The bar does not open</dt><dd>Open Ouros from Applications first. Tap and release the Option key on the right of the space bar by itself. If it works in Ouros but not from another app, open <strong>System Settings → Privacy &amp; Security → Input Monitoring</strong> and enable Ouros. Follow any request to quit and reopen it, then try again from another app. You can turn this access off in the same Settings pane. See <a href="/app/permissions">Permissions</a>.</dd><dt>No app or file matches</dt><dd>Check the name you typed and the selected mode. For a file, check the folders selected in Ouros Search Settings. Try an app whose name you know, such as Safari, using <a href="/app/first-action">Your first action</a>.</dd><dt>Focus lands in the wrong place</dt><dd>Record which app was active before and after the bar closed. The source app alone does not establish the cause.</dd><dt>A feature is greyed out</dt><dd>Read <a href="/app/not-built">What is not built yet</a>, then check that feature's permission and visible error.</dd><dt>A command reaches another mode</dt><dd>Compare the attempted input with <a href="/app/search-and-modes#prefixes">Prefix routing</a>. The <a href="https://ouros.md/docs/troubleshooting#recovery">recovery helper</a> previews routes without running the input.</dd><dt>A Gateway action fails</dt><dd>Check the status and error code below. Keep an unresolved request's original identity before retrying.</dd></dl>

<h2 id="recovery">Find a recovery check</h2>

<p>Read the recovery checks below, or use the <a href="https://ouros.md/docs/troubleshooting#recovery">interactive recovery helper on the Ouros website</a>. It previews routing and filters checks without executing your input.</p>

<h2 id="recover-forbidden">403 / Forbidden</h2>

<p>A 403 alone does not identify the cause. Note whether it appeared in website sign-in, the Assistant, Music or an API request. Keep the URL path, time and error code; leave out authorization headers and cookies.</p><dl className="docs-steps"><dt><code>origin_forbidden</code></dt><dd>Start sign-in from the original Ouros site. Do not disable browser security or origin checks.</dd><dt><code>application_forbidden</code></dt><dd>The Gateway rejected the application identity. Ask the integration owner to check the application configuration; do not share or replace tokens in a support message.</dd><dt><code>forbidden</code> or <code>tenant_scope</code></dt><dd>Confirm the intended account and workspace with its administrator. Signing in again does not promise additional access.</dd><dt>Music reports a 403</dt><dd>Spotify rejected the connection's permission. Check the Music connection rather than macOS file permissions.</dd></dl><p>If the code is missing, the cause remains unknown. Record the exact redacted message before escalating. Confirm recovery by completing the original action with the intended account.</p>

<h2 id="recover-signin">401 / Sign in required</h2>

<p><strong>When sign-in started from Ouros:</strong> keep the app running and finish in the browser page it opened. After signing in, choose <strong>Connect Ouros</strong> if that page asks you to connect. If it shows a device code, compare it with the code shown in Ouros before choosing <strong>Connect Ouros X</strong>. Approve only a request you started. Return to Ouros and wait for its account status to confirm the connection.</p><p>If the browser cannot return to Ouros or the request has expired, start sign-in again from Ouros to open a fresh request. Keep the app running through the return. Do not copy sign-in codes or callback addresses into another page.</p><p>The dashboard asks you to sign in when authentication is missing. Keep your draft before opening <a href="https://ouros.md/login" target="_blank" rel="noopener">sign-in in a new tab</a>. Return to the original tab afterward. If the action still returns 401, record the route and redacted error.</p>

<h2 id="recover-pending">202 / 409 / Reconciliation pending</h2>

<p><code>dispatch_outcome_unknown</code>, <code>dispatch_requires_reconciliation</code> and <code>dispatch_pending_reconciliation</code> mean the dispatch outcome has not settled. Keep the original session ID and idempotency key private.</p><p>The dashboard retries the pending stream a bounded number of times. If it remains unresolved, note the time and state for the integration owner. Do not start a second run or generate a fresh key to bypass reconciliation. See <a href="/errors">Errors and retries</a>.</p>

<h2 id="recover-routing">The wrong surface opened</h2>

<p>A leading symbol can route the same words differently. Check <a href="/app/search-and-modes#prefixes">what the symbol consumes and keeps</a>, then compare the destination with what you intended.</p><p>The current native router routes automatically from rest. An explicitly selected mode takes precedence. These are source-level checks; confirm them against your installed version.</p>

<h2 id="recover-voice">Voice Wake does not respond</h2>

<p>Check that Voice Wake was explicitly enabled, speech recognition is permitted, microphone access is allowed and on-device recognition is available. Look for the error shown by the Voice Wake setting.</p><p>Recording, dictation, secure input and native dialogs can suspend listening. Finish the active task, then try again. Do not grant unrelated permissions or hide the macOS microphone indicator.</p><p>If it still fails, record the app and macOS versions, the permission granted and the visible error. These checks do not certify the microphone lifecycle of a particular installed build.</p>

<h2 id="recover-keychain">Music repeatedly asks for a Keychain password</h2>

<p>A recorded regression allowed automatic Music status reads to open password dialogs when the saved item did not accept the helper signature. Cancel the unexpected prompt; do not keep entering a password or delete your Keychain.</p><p>Note whether the prompt appeared while opening Music settings or checking the connection. Record the app version and requester name. The source repair makes automatic reads fail without prompting, while connection changes stay explicit. Check whether your installed build includes the repair before treating it as resolved.</p>

Keep credentials and private logs out of the record.</p><div className="codeblock"><pre><code>App or browser version: [version] macOS version, if relevant: [version] Surface and URL path: [where it happened] Time and timezone: [when it happened] HTTP status and error code: [if present] Expected result: [what you expected] Observed result: [what happened]</code></pre></div>
